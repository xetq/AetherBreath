# 审批器 v2 —— 动词—目标绑定 与 后果分区（2026-09-11）

> v1 规格文档见 `docs/审批器-规格与链路-v1截断20260910.md`。本文只写**改了什么、为什么改、
> 用什么证据改的**；契约细节在 `agent/approvals/README.md`。

## 一、起因

v1 的判定是**共现式**的：整段参数里扫到动词 + 扫到路径 → 成立。重放 1327 条重构前的
真实工具调用，逐条定位到三类假弹窗（都是当天发生的）：

| 真实意图 | 旧引擎给出的目标 |
|---|---|
| 往工作区写一个分析脚本（体内含盘符常量） | 「对 `c:/` 执行：移动/重命名、写入/覆盖」 |
| 字符串小写替换 `cmd.lower().replace('a','b')` | 「移动文件」 |
| `cp 盘内/secret.txt D:/backup/` | 「对 盘内/secret.txt 执行写入」——其实只是读 |

同时量到两个致命漏判（v1 的入口判据是「路径在系统盘」）：

```
改 agent/approval.py            -> pass      执行者可无损改写审查者
往 approval_rules.jsonl 追加免审 -> pass      等于自签免审
```

## 二、改了什么

1. **词法层新增「动作点」** `actions[] = {lang, word, args, kw, redirect, mode, recv_paths, cwd}`。
   动词与它的**直接实参**成对交付，规范层不再自己扫全文。
2. **heredoc 角色由命令性质决定**：喂给解释器 = 代码（递归解析）；
   喂给 `cat`/`tee` 这类 = 数据（提及层）。数据里的常量不再是目标。
3. **方向表**：`DEST_LAST` / `FIRST_ONLY` / `ALL_TARGET`。
   只读动词带重定向只算目标被写；移动连源一起算；写入取「最后一个**像路径**的实参」。
4. **取向反转**：认不出类别且无写信号的动词不算改动（`python x.py`、`git diff y` 是引用）。
   先前"未知即保守"在历史重放里凭空造出 125 条弹窗。
5. **补 `engine.selfmodify` 规范**：审批链/引擎/账本/免审规则/.env/主程序被写删移必须人批，
   **只问不拒**（若不可授权，规则一旦写错我就再也修不了自己）。
6. **两处 fail-open 关闭**：规范内部异常 `continue` → 升级为 ask；解析失败的代码体走
   `opaque` 通路 → ask 且明写「目标未能确定」。
7. **合并卡整包透传**（`approval_adapter.py`）：手工搬字段的同类病犯过三次。

## 三、效果（可复算）

| 指标 | v1 | v2 | 说明 |
|---|---|---|---|
| 重构前 1327 条调用的弹窗数 | 76 | 78 | 总数持平 |
| 其中系统盘规范 | 72 | 39 | 假弹窗（提到即定罪）消失 |
| 其中引擎自留地 | **0** | **37** | 此前零覆盖 |
| 三条命名误报 | 全弹 | 全 pass | 已钉成 `tests/test_approval_binding.py` |
| self_check / 断言 | 14 / 93 | 14 / 93 | 全绿，旧契约仅 1 条正当更新 |
| 单次判定耗时 | 0.05~0.67ms | 0.07~0.93ms | 同量级（stat 收紧后） |

## 四、还欠着什么

- **grants 仍无消费者**：`approved_prefixes` 没人读，「批 A 干 B」与拼接绕过拦不住。
  正解是在执行体子进程装 `sys.addaudithook` 按授权前缀校验真实访问，不是继续在命令行上猜动词。
- **覆盖面只到"文件系统"**：注册表、外发网络、下载执行、杀进程、改系统时间仍为 pass。
  架构已备好——`approvals/` 里加一个文件即生效（见 README §四与 `_template.py`）。
- **动词表本质仍是枚举**：绑定层把「误报」压下去了，但新出现的落盘 API（第三方库、
  自写 C 扩展）仍会漏。兜底是 grants/audithook，不是更大的表。
