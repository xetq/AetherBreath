# AetherBreath 项目总统规划

> **版本**：v3.0（概念框架）
> **日期**：2026-09-03
> **性质**：设想与方向，非锁定设计


## 一、项目定位

AetherBreath 是一个**可定义的智能体操作系统**。

它不是被写死的“万能助手”，而是一个**空壳引擎**。用户通过定义“方向”，让这个引擎长出特定的能力、知识、行为模式，成为一个垂直领域的专用智能体。


## 二、核心理念

1. **用户定义垂直方向**
   - 启动时，用户指定方向（如“医学为主，经济为辅”）
   - Agent 根据方向加载对应的能力包

2. **一切皆可复刻**
   - 能力包、工具集、行为模式都作为“数据”存在
   - 任何东西都可以被克隆、修改、继承、组合

3. **内核稳定，外围进化**
   - 执行引擎一旦稳定，不再改动
   - 所有新能力都在外围以“数据/配置”的形式注入

4. **Agent 也是造物主**
   - 主 Agent 可以创建子 Agent
   - 子 Agent 可以修改父 Agent 或其他 Agent 的配置

## 四、核心模块构想

### 1. 方向定义模块
用户定义 Agent 的“垂直方向”，相当于给 Agent 画一条“成长轨迹”。方向决定了 Agent 的行为边界和能力倾向。

### 2. 能力组合模块
Agent 的能力由多个维度组合而成：行为模式（提示词）、可用工具、技能包、配置参数、记忆体系。这些维度可以自由组合，形成不同的 Agent 变体。

### 3. 蓝图系统
每个 Agent 的“配方”被保存为一个蓝图。蓝图是一个 Agent 的完整定义，可以复用、克隆、修改、继承。蓝图之间的差异，就是不同 Agent 之间的差异。

### 4. 技能系统
技能是“能力的组合说明书”。一个技能描述了一组工具如何协同完成某项任务。Agent 学习技能 → 掌握复杂能力 → 组合技能 → 解决更复杂的问题。

### 5. 多 Agent 协作
多个 Agent 可以协同工作，分工明确（如规划者、执行者、评审者）。协作模式可以是顺序、并行、层级等。

### 6. 自我进化
Agent 可以通过工具修改蓝图、创建新技能、调整自身配置，实现自我迭代。进化由用户授权，在可控范围内进行。


## 五、Agent 与子 Agent 的关系

主 Agent 可以创建子 Agent。子 Agent 继承主 Agent 的部分能力，也可以拥有自己的专属能力。

子 Agent 的创建方式是：主 Agent 读取一个“构建模板”，根据用户需求填充参数，生成一个新的蓝图，然后实例化为一个独立的子 Agent。

子 Agent 可以独立运行，也可以与主 Agent 或其他子 Agent 协作。


## 六、Skill 系统的概念

Skill 不是工具，而是“工具的使用说明书”。

一个 Skill 描述的是：为了完成某类任务，应该按什么顺序调用哪些工具、如何处理中间结果、如何判断成功或失败。

Agent 通过读取 Skill 来获得“做某事的方法”，而不是被硬编码地教会如何做某事。


## 七、进化的方向

AetherBreath 的进化不是“代码更新”，而是“数据更新”：

- 用户调整方向定义 → Agent 行为变化
- Agent 修改自身蓝图 → Agent 能力变化
- Agent 创建新 Skill → Agent 掌握新方法
- Agent 克隆并修改另一个 Agent 的蓝图 → 群体进化

进化由用户定义边界（如“只能在医学领域内进化”），由 Agent 在边界内探索。


## 八、设计原则

1. **内核稳定**：执行引擎一旦稳定，不再改动
2. **外围可变**：所有可变部分都放在配置文件/数据文件中
3. **用户定义**：用户决定 Agent 往哪个方向发展
4. **Agent 自主**：Agent 在用户定义的边界内自主决策和进化
5. **可追溯**：每一次进化都有日志记录，可回滚


## 九、长期愿景

> **“AetherBreath —— 一套由用户定义方向的智能体自我繁殖系统。”**

它既不是通用助手，也不是固定垂直 Agent，而是一个**“生长框架”**。用户播种方向，Agent 生长出能力。用户收获一个专用智能体，而不是一个通用工具。


## 十、一句话总结

**“给 Agent 一个方向，它自己长出来。”**

---

这份规划可以作为 AetherBreath 的“宪法”。你可以随时修改、调整，但核心理念——**用户定义方向，Agent 自我生长**——保持不变。
