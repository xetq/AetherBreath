## 1. 定位与边界

**管什么**：模型发出的**工具调用请求**能不能传到任务编排器。只此一件。

**当前覆盖的审批类别**（唯一一类，其余按需再加）：
- 系统盘（默认取 `SystemDrive`，绝不硬编码盘符）上的**直接写入 / 删除 / 移动重命名**。

**不管什么**：
- 读操作。venv、解释器、site-packages、AppData 全在系统盘，一次 import 就是上百次读；读也弹会把人训练成闭眼点「允许」，**那比没有审批更危险**。
- 不碰本地盘的 8 个工具（`NON_FS_TOOLS`）：其参数里的路径字样只是文本（搜索词、URL、提问）。
- 编排行为：该串行串行、该并行并行仍由 `task_orchestrator` 决定，审批只控制请求能否传过去。
- 注册表 / 计划任务 / 服务 / WMI：未覆盖（见 §10）。

**它不是安全边界，是「威慑 + 提高门槛 + 全程留痕 + 阻止无意越界」。** 想要绝对边界只有 OS 级隔离（Job Object / ACL 降权 / 只读挂载）。这条定位写在卡片可见处，不给虚假安全感。

## 2. 整条 trace

```
LLM 返回一批 tool_calls
  └─ agent/agent.py  L450 主循环
       ├─ 解析参数（JSONDecodeError → 直接补 ❌ tool 回执，不进审批）
       ├─ 攒 audit_items = [(tc, name, args)]
       └─ 从 approval import gate_batch        ← 审批唯一入口（整批一次）
            │
            ├─ inspect_one(tool, kwargs, session_id, cwd)      【逐项判定】
            │    ├─ mode()==off                          → pass
            │    ├─ approval_lex.lex(tool, kwargs)       → control / operands / mentions
            │    │     · shell：引号感知切段 → 每段 {cmd, text} + WRAPPERS/INJECT/DATA 分类
            │    │     · python：ast.parse → Call 链为指令、sink 位置实参为操作数、
            │    │       赋值右侧与字面量接收者方法为提及；注释天然被 AST 丢弃
            │    │     · 解释器注入位（-c / -Command / os.system / $( ) / 反引号）递归展开
            │    ├─ _forbidden_at_cmdline(lex)  命中 → block（不给授权入口）
            │    ├─ mention 命中禁区 → ledger(payload_hit)，只留痕不打扰
            │    ├─ tool ∈ NON_FS_TOOLS        → pass
            │    ├─ extract_paths(operands) / (mentions) 分开归一
            │    ├─ 无盘内操作数               → pass
            │    └─ 遍历 approvals/ 规范：applies(ctx) → finding(ctx)
            │          quiet=True → quiet（记账放行）    block=True → spec_block
            │          否则 → ask，并算 critical / reversibility / purpose
            │
            ├─ 有任一 block            → 整批拒（batch_block）
            ├─ 无 ask                  → 整批放行（quiet 项计入 grants）
            ├─ SCOPES.match() 全命中   → 免打扰（scope_allow，仍计入 grants）
            └─ 剩下的 ask 整批一起问：
                 get_port().request_many(reqs)
                   ├─ WebUIPort：approval_request(单条) / approval_batch(合并卡)
                   │            SSE 下发 → Event 等待 → /approval/answer 回投
                   └─ ConsolePort：纯文字，「E 你的话」同样支持说明
                 verdict 逐项记账 → 批次结算
                   ├─ 全批批准 → 原样进 parsed_calls → 编排器
                   └─ 否则     → 每项补一条 role=tool 回执（四种文案，见 §5）
                 choice=B/D → SCOPES.add()（受 MIN_SCOPE_SEGMENTS 护栏约束，
                                 被挡则记 scope_denied，批准本身仍有效）
```

**中断路径**：等待裁决时被 Ctrl+C / 停止按钮打断 → 引擎记 `batch_cancelled` 后向上抛 → `agent.py` 为整批补闭合 tool 回执，绝不留「有 tool_call 无响应」的断头（那会让下次加载直接 400）。

## 3. 判定标准

### 3.1 四种决策

| 决策 | 含义 | 对模型的表现 |
|---|---|---|
| `pass` | 不需审批 | 正常执行 |
| `quiet` | 免打扰（记账放行） | 正常执行，账本留痕 |
| `ask` | 需要人批 | 弹窗；批准才执行 |
| `block` | 绝对禁区 | **不申请审批、不给放行按钮**，直接拒 |

### 3.2 词法三层（本系统的核心判据）

角色由**命令的性质**决定，不由引号决定。

| 层 | 内容 | 参与什么 |
|---|---|---|
| `control` 指令层 | 命令词、flag、重定向符、函数名链、注入位展开后的二级代码 | 禁区 + 动词判定 |
| `operand` 操作数层 | 真正被读写删移的对象 | 审批目标（区域判定） |
| `mention` 提及层 | 正文、注释、文档字符串、输出类命令的参数 | **不判定**，只提路径留痕 |

动机：判定曾经直接扫参数全文，结果「在文档里提到危险词」就被拦下 —— 引擎把「我在说什么」当成了「我要干什么」。连构造该 bug 的测试用例都写不出来（现场被咬 10 次）。

规模：`DATA_COMMANDS` 17、`SILENT_CALLS` 40、`INJECT_FLAGS` 11、`WRAPPERS` 16、`SHELL_SINKS` 9。

### 3.3 绝对禁区（18 条，按形态自动分三档，判法不同）

| 档 | 条数 | 判法 | 理由 |
|---|---|---|---|
| `CMD` 单词型 | 6 | 只与命令词**精确等值**（并剥 `.exe/.bat/.ps1/...` 后缀） | 做子串匹配时，连 `grep` 查端点名这种纯只读都会被拦 |
| `PHRASE` 短语型 | 10 | 只匹配「从命令词起算」的**段文本前缀** | 提权/包装前缀让出段首，否则配不上 |
| `PATH` 路径片段型 | 2 | 移出命令位，交规范层**与动作同时成立**才生效 | 读 hosts 是排障常态，写它才是灾难 |

三档由引擎按形态自动分类，不手维护三份表（迟早漏一条）。

### 3.4 动作判定（`cdrive_files.CMD_WORDS`，写入 35 / 删除 12 / 移动 7）

- 按**命令词或函数名末段精确等值**，绝不做裸子串。
  旧版子串匹配造成的事故：`os.remove` 同时命中「删除」和「移动」（措辞张冠李戴）、`model.save` 命中「删除」（因为 mo-**del**）、`json.dumps`/`copy.deepcopy` 命中「写入」。
- 写入还看**事实**：`redirect_write`（`>`、`>>`）与 `open_modes` 含 `w/a/x/+`；`open(p)` 只读不再被当写入。
- 接收者是字面量或容器字面量的方法判为**数据操作**（`"…".replace()` 不是移动文件），但 `os.replace(a,b)` 仍是移动。

### 3.5 区域与档位

- `QUIET` 12 个前缀（临时/缓存/venv/node_modules/__pycache__ 等）→ 记账放行。
- `CRITICAL` 10 个区（Windows、Program Files、ProgramData、Boot、EFI、启动目录等）→ 同一审批，措辞更重，卡片标红，**默认不勾选**。
- 路径归一：小写盘符、正斜杠、绝对化（cwd 参与）、git-bash `/c/…` 还原。
- 汉字**不是**路径停止符（本项目就有中文目录名），但 CJK 标点与全角形式是（`U+3000-303F`、`U+FF00-FFEF`）。

### 3.6 作用域与深度护栏

`once` / `session` / `persistent` 三档。前缀存**目标文件的父目录**（同目录换名不再重复问）。

**护栏 `MIN_SCOPE_SEGMENTS = 3`**：盘符后不足三段一律不签发。
来源是真实事故（账本 16:15）：对某文件点「永久允许」，父目录即 `C:\Users\<你>` —— 桌面/文档/下载全部免审；同批还签发了 `C:\Windows`。一次点击拆掉审批门。
被护栏挡下时**批准本身仍然有效**，并记 `scope_denied` —— 不留痕等于骗人。

## 4. 批次与失效机制

- **批次原子**：同批只要有一项未获批，整批一个工具都不提交（含本来不需审批的）。理由：模型把它们放同批说明是一个意图的整体，只做一半可能留下比全不做更糟的中间态。
- **四种未通过文案必须可区分**（模型需要知道「主人没看到」和「主人说了不行」是两回事）：
  1. `本次操作需审批，用户拒绝`
  2. `本次操作需审批，用户未响应（超时）`
  3. `本次操作需审批，但当前环境没有可用的审批通道`
  4. `同批次内有其它操作未获批，本批全部未执行`
  5. `本项已获主人批准，但同批次内另有操作未获批准…`（已批项专属 —— 若写成「用户拒绝」，模型会放弃一条已获授权的路径）
- **失效一律 fail-closed**：无通道 / 超时 / 通道异常 → 拒。引擎自身异常时默认 `deny`（曾经默认 `allow`，结果一个笔误——引用了不存在的常量——让所有该弹窗的操作静默放行且界面毫无异常）。
- **裁决可附言**：`Decision.note`。未放行项的文案统一附「主人补充：…」，并汇总整批说明；上限 400 字，通道只限长与空白、**绝不改写内容**（改写就是替主人说话）。批准的附言只进账本，不改执行路径。

## 5. 交互协议（卡片）

| 字段 | 来源 | 说明 |
|---|---|---|
| AB 想要 / 依据 | `intent` / `reason` | 动作 + 目标 + 是否关键区 |
| notes 第 1 行 | `purpose` | **AB 自述用途**（取命令首行 `#` 注释）；没写则显示「⚠️ AB 未声明这次操作的目的 —— 建议先问它要干什么再批」 |
| notes | `reversibility` | 可逆性：新建可撤回 / 覆盖原内容丢失 / 删除不可自动恢复（引擎查目标是否存在后判定） |
| notes | `user_request` | 你的原话（引擎 `last_user_text()` 自取，`agent.py` 只传 conversation） |
| 展开区 | `source_code` | 原始参数 |
| 输入框 | `accepts_note` | 由引擎下发决定是否显示 |

**五结算按钮与键盘映射（可用性与 `disabled` 同源，键盘不得绕过）**

| 键 | 按钮 | 可用条件 | 二次确认 |
|---|---|---|---|
| 1 | ⚪ 始终批准 | 有勾选 | 是 |
| 2 | 🟢 批准 | **全部勾选** | 否 |
| 3 | 🟠 批准并返回AB | 有勾选**且不满全部** | 否 |
| 4 | 🔴 全部拒绝 | 始终 | 否 |
| 5 | ⛔ 全部拒绝并终止 | 始终 | 是 |
| Esc | 同 4 | 始终 | 否 |

焦点在输入框内时，数字键与 Esc **一律不裁决**（否则你打「ProgramData 1」就当场把整批改掉）。

**免审规则面板**：右栏「上下文」→「免审规则」。列出**当前真正生效**的规则（永久 + 本会话会话级），每条可撤销，底部「撤销全部」两段式确认。撤销同时改内存与磁盘（只清文件会残留到进程里、重启后诈尸）。

## 9. 变更纪律（后续修 bug 必须遵守）

1. **重启才生效**：`approval*` 与 `bridge`/`adapter` 在每个进程启动时 import 一次。改磁盘 ≠ 改当前会话。判定生效的硬办法：看账本最近一次 `self_check` 时间是否晚于文件 mtime。
2. **只测生产位置**：`tests/` 里已有断言 —— `A.__file__` 必须是 `agent/approval.py`，否则当场炸。（真实事故：`sys.path` 曾把「激活版」排在前面，新代码一行没测还报了全绿。）
3. **质量门是 `tsc --noEmit` 的退出码**，不是 `vite build` 成功（build 不做类型检查）。对产物 grep 只能证明代码进了包，**不证明数据通路通**。
4. **跨层新增字段一律整包透传**，不写白名单。（同类病三次发作：reducer 漏抄 `accepts_note`、网关三处丢 `note`、用例读部署包。）
5. **边界用例必须用非空形状**：撤销类操作只测「全部撤销」会让循环体不执行，掩盖坏引用。
6. **写文档/测试数据不留字面禁区词**：一律运行期从 `FORBIDDEN` 按形态特征取（尾空格 / 长度 / endswith），包括注释。
7. **行尾**：`agent_tools/`、`agent_webui/backend/agent_client.py`、`ContextPanel.tsx`、`WorkspacePanel.tsx` 曾/现为 CRLF 少数派；改前探测、写回还原，绝不用 `open(p,'w')` 写 CRLF 文件（会叠成 `\r\r\n`）。
8. **改 `bridge._wrap_tool` / `finally` 等咽喉层后**，第一个动作是发一条最小调用确认能正常返回，再谈功能。

## 10. 已知未封（诚实清单，不当作已解决）

| # | 缺口 | 性质 | 说明 |
|---|---|---|---|
| U1 | 赋值后拼接路径：`p = 盘符; open(p + "/Windows")` | **漏判** | 静态判定天花板（停机问题级）。根治靠行为层 audit hook（Grant 消费者），未实施 |
| U2 | 两跳执行：先落盘脚本到别的盘，再运行它 | **漏判** | 第二步代码里不含系统盘字样 |
| U3 | **跨段串味**：动词来自 A 段、目标来自 D 段的复合命令 | 误拦 | 本轮事故。词法层全局合并 control/operands，未做「命令词只对自己参数负责」的按段配对 |
| U4 | **文本载体参数**：`git commit -m "…"`、`--message`、`--description` 的引号内容被当操作数 | 误拦 | 待加 flag 名单；这是 U3 事故的另一半成因 |
| U5 | 冷门写文件命令未入动词表（带内编辑参数的流编辑器等） | 漏判 | 低概率 |
| U6 | 注册表、计划任务、服务、WMI、驱动、防火墙 | 未覆盖 | 不是文件路径，需另立 provider 规范 |
| U7 | `-EncodedCommand` 的 base64 载荷无法静态审 | 漏判 | 词法层已记入 `opaque` 字段，尚无消费者 |
