## 1. P0 — 枚举名字表在"名字可拼"的宿主语言里不闭合

`cdrive_files.py` 的 `CMD_WORDS["删除"]` 现有 20+ 个 Windows API 别名。上一轮 `SHFileOperationW` 被静默放行后，
修法是往表里加名字。**加名字追不上改名字。**

真值表（靶：`C:/Users/<user>/Desktop/test_delete_me.txt`；通路 = `execute_shell` + `python - <<PY` heredoc，与真机弹窗那次同形）：

| # | 删除形态 | 现状 | 根因 |
|---|---|---|---|
| ① | `ctypes.windll.shell32.SHFileOperationW(p)` | `ask` ✅ | 名字在表里 |
| ② | 同上但裸名 `SHFileOperation` | **`pass` ⚠** | 少一个 `W`。表里只有 `…w`/`…a`；ctypes 属性访问会自动解析后缀 → **真的能删** |
| ③ | `getattr(m, 'SHFile' + 'OperationW')` | **`pass` ⚠** | 名字是运行时拼出的字符串，任何名字表对它免疫 |
| ④ | `os.remove(p)` | `ask` ✅ | |
| ⑤ | `Path(p).unlink()` | `ask` ✅ | |
| ⑥ | `os.unlink(p)` | `ask` ✅ | |
| ⑦ | `shutil.move(p, D:/gone.bin)` | `ask` ✅（移动/重命名） | |
| ⑧ | `open(p,'r+b').truncate(0)` | `ask` ✅（写入/覆盖） | |
| ⑨ | `os.system('del …')` | **`pass` ⚠** | `os.system` 不在 `SHELL_SINKS`；`subprocess.run(shell=True)` 在，所以 ⑩ 被拦 |
| ⑩ | `subprocess.run([...], shell=True)` | `ask` ✅ | |
| ⑪ | `ctypes.windll.kernel32.DeleteFileW(p)` | `ask` ✅ | |
| ⑫ | `win32file.DeleteFile(p)` | `ask` ✅ | |

现状 **9/12**。三个漏网里 ②③ 同族（**不可靠加名字修**，只能换判据），⑨ 是漏 sink 项（**可修**）。

### 建议的一刀：把"识别动词"换成"承认看不见"

不是加别名，而是加一条 fail-closed 规则：**动词由运行时构造 ⇒ 静态不可判定 ⇒ 按最危险处理**。
与引擎既有取向一致（"宁误拦不漏拦"、`AETHER_AUDIT_ON_ERROR=deny`）。

```python
# agent/approvals/cdrive_files.py
_RE_UNDECIDABLE = re.compile(r'ctypes\.windll|getattr\s*\(|__getattr__|importlib')

def finding(ctx):
    ...
    acts = _acts(ctx)
    if not acts:
        # 名字是运行时构造的 => 静态看不到动词。不猜它要干什么，按最危险处理。
        if targets and _RE_UNDECIDABLE.search((ctx.get("control") or "").lower()):
            acts = ("删除/改写（目标名由运行时拼装，静态不可判定）",)

```

实测效果（同一张真值表重跑）：

| 形态 | 现状 | 提案 | 误伤？ |
|---|---|---|---|
| ② 裸名无后缀 | `pass` | **`ask`** ✅ | — |
| ③ getattr 拼名字 | `pass` | **`ask`** ✅ | — |
| ⑬ `os.path.exists(盘内)` 只读探测 | `pass` | `pass` | 不误伤 ✅ |
| ⑭ `ctypes.windll.kernel32.GetTickCount()`（无路径） | `pass` | `pass` | 不误伤 ✅ |
| ⑮ `CreateFileW("C:/Windows/win.ini")` 读 | `pass` | `ask` | 保守方向，可接受 |

拦截面 **9/12 → 12/12**，代价一条正则；并且**表可以变短**（以后不必再逐个点 `…W`/`…A` 变体）。
`os.system` / `os.popen` 补进 `approval_lex.py` 的 `SHELL_SINKS` 即收掉 ⑨。

## 3. P2 — 审批卡：注释立的规矩，代码自己没守

`ApprovalCard.tsx` L130-131 原文：

> 「可用性判定必须与按钮 disabled 同源：否则键盘 1~5 会绕过限制，等于留一条"没全勾也能按批准"的后门」

但 5 个按钮各自手写 disabled（L225-244），与 `usable()`（L132-135）**不是同一个函数**。枚举全部状态求得的真值差：

| 总项 | 勾选 | allChecked | 动作 | 键盘可触发 | 鼠标可点 | 偏差 |
|---|---|---|---|---|---|---|
| 1 | 0 | False | `always` | False | **True** | ⚠ 鼠标独有 |
| 3 | 0 | False | `always` | False | **True** | ⚠ 鼠标独有 |
| 1 | 1 | True | `return` | True | **False** | ⚠ 键盘独有 |
| 3 | 3 | True | `return` | True | **False** | ⚠ 键盘独有 |

**两条实际后果：**

1. `always`（⚪ 写永久规则，最危险的动作）按钮**从不 disabled**。勾选 0 项时它显示"始终批准（0）"、可以点，
   点进去 `usable()` 返回 False → **静默无反应，连二次确认都不进入**。用户视角就是"按钮坏了"。
   **危险动作的失败模式不该是无声。**
2. `return`（批准并返回AB）的 disabled 多一个 `allChecked`，`usable()` 里没有 → 全勾时**鼠标点不动、键盘按 3 能触发**。
   与注释承诺的"同源"正好相反。

### 建议：表驱动，判据只写一次

```tsx
// 一份表 = 文案 / 键位 / 危险确认 / 可用性；判据与 disabled 同源，不再各写一遍
const ACTS = [
  { mode:'always',   key:'1', need:1, ok:(a,c)=>c>0,      label:(a,c)=>'⚪ 始终批准（'+c+'）' },
  { mode:'approve',  key:'2', need:0, ok:(a,c)=>a,        label:(a,c)=>a?'🟢 批准（'+c+'）':'🟢 批准（需全部勾选）' },
  { mode:'return',   key:'3', need:0, ok:(a,c)=>c>0&&!a,  label:(a,c)=>'🟠 批准并返回AB（'+c+'）' },
  { mode:'denyAll',  key:'4', need:1, ok:()=>true,        label:()=>'🔴 全部拒绝' },
  { mode:'denyStop', key:'5', need:1, ok:()=>true,        label:()=>'⛔ 全部拒绝并终止' },
] as const
```

L132-135 与 L225-244 折叠到这张表 → **约 −20 行，顺手修掉 4 处不一致**。

另两处小的：`useEffect`（L82-99）**无依赖数组**，每次渲染重挂 keydown 监听（流式渲染期高频）；
`windowOf` 的 `[5,3600]` 与后端 `timeout_sec()` 的 `[5,3600]`、adapter 的 `max(int(x),5)`（**无上界**）是三处独立真值，见 P5。

## 6. N1 — 明示不动的一刀（附理由，免得下一个人再来提）

`approval_lex.py` 565 行手写引号 / 重定向 / heredoc / 命令替换扫描，`imports` 里只有 `re` 没有 `shlex`。
按"标准库优先"的梯子这看着像最该砍的一刀。**不砍：**

1. `shlex` 只给 token 流。本引擎要的是**角色分层**（`control` / `operand` / `mention`）——这个词是动词、那个词是被动的对象、
   那段只是正文里提到。这层 `shlex` 给不了，换过去照样得写。
2. `_scan_shell` 里有 `shlex` 语义不等价的东西：`<<-` 带 tab 的终止符匹配（L204-242）、`$()` 嵌套深度（L164-174）、
   反引号二级代码位（L156）、`&&`/`||` 分段（L183-188）。而 Windows 反斜杠在 `shlex` posix 模式下的转义规则与 bash 不同
   ——**换错的后果是开门，不是变慢**。
3. 技能自己划了线：*"Never simplify away: input validation at trust boundaries … security measures"*。这里是 trust boundary 本体。
   省 100 行买不回一次漏判。

同理，`_scan_shell` 那 130 行状态机是全文最贵也最值的一段代码。
