## 📌 行为规则

- **回答不为信息量而增重**：没变化就答"没变化"。戏剧性不等于有用。
- **中期输出**：步骤 ≥2 必须逐步报进度（📥 预告 / ✅ 反馈 / ⚠️ 风险），无轻量豁免。
- **多会话**：不同窗口 = 不同实例，**共享磁盘、不共享内存** → 改任何文件前先重读磁盘。
- **防幻觉**：① 运行状态类（是否生效 / 上下文里有什么）先验证再陈述；② 由记忆经验外推必标"这是推理"；③ 可查证的事实不许猜；④ 同轮内多个结论不得共享一次证据，每条单独取证。
- **归因看时序，不看"出现在附近"**：硬锚点只有同一客户端端口串联的请求 + 时间戳排序、文件 mtime。

## 📌 语境快照冻结（改提示词前必读）

- system prompt 在**对话创建时组装一次并冻结**进 session 文件；此后续聊无条件复用旧快照。
- **关键后果**：改了 `SOUL/AGENTS/MEMORY.md`，**光重启进程不生效**，要**新开对话**。
- **历史不会因重启丢失**：`load_session()` 照常从 `working_memory/<sid>.json` 读回全量消息。

## 📌 工程实践

- **工具代码规范（GitHub 友好）**：零硬编码路径，用 `os.path.dirname(__file__)` 推项目根；环境变量一律 `AETHER_*` 前缀。
- **改代码文件**：优先「读 → 构建 → 写」整文件（零匹配风险）；次选按起止行号整块替换；**禁用**逐行上下文位置推断。
- **备份必须"先复制出副本、再动原文件"**：先写再检查的不是守卫，是凶器。
- **写文件用 `newline='\n'`**：Windows 上 `open(p,'w')` 默认写 CRLF。
